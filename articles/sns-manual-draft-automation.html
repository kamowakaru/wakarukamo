記事公開時のSNS投稿文だけを自動生成する方法｜API不要の運用

記事公開時にXとThreadsへ完全自動投稿せず、コピペ用原稿とUTM付きURLだけをGitHub Actionsで生成する方法を解説します。

結論

記事公開をSNSへ知らせたいもののAPI料金や設定が負担になる場合は、投稿そのものではなく、投稿文と計測用URLだけを自動生成する方法があります。

ワカルカモでは、記事Markdownを追加するとX用2案とThreads用1案をTXTへ出し、人が内容を確認して投稿する運用にしました。

完全自動投稿をやめた理由

最初は記事公開と同時にXへ自動投稿する仕組みを検討しました。しかし、X APIは料金体系を確認する必要があり、開設直後のサイトでは投稿数に対して準備が大きくなります。

また、自動投稿ではタイトルや説明に間違いがあっても、そのまま公開される可能性があります。手動投稿なら、リンク先とサムネイルを最後に確認できます。

X APIの料金を調べた経緯は、X APIで記事を自動投稿する方法は有料？で紹介しています。

自動化する範囲

記事データから次を作ります。

  • 記事タイトル
  • 記事の説明文
  • X用の要点型投稿
  • X用の問いかけ型投稿
  • Threads用の体験に寄り添う投稿
  • SNS別のUTM付きURL
  • 投稿前チェックリスト

出力先は次のように記事slugと同じ名前にします。

content/articles/ga4-guide.md
social-drafts/ga4-guide.txt

GitHub Actionsで原稿を作る

記事Markdownが変更されたとき、記事HTMLを生成したあとにSNS原稿生成スクリプトも実行します。

原稿ファイルはリポジトリへ自動コミットします。投稿APIは呼び出さないため、SNSのアクセストークンを登録する必要はありません。

XとThreadsで文章を変える

Xは短い文章で要点とリンクが分かる形にします。Threadsは、なぜ調べたのか、どこで困ったのかを少し詳しく書きます。

同じ本文をそのまま両方へ貼るより、媒体に合わせた下書きを用意したほうが修正量を減らせます。

ただし、自動生成文が毎回同じ言い回しにならないよう、実際の経験を一文追加してから投稿します。

UTMで流入元を分ける

XのURLにはutm_source=x、Threadsにはutm_source=threadsを付けます。GA4でどちらからアクセスされたか比較できます。

設定例は、GA4でXとThreadsの流入を確認する方法で詳しく説明しています。

投稿前に確認すること

  • 公開記事をブラウザで開けるか
  • タイトルや説明に誤字がないか
  • サムネイルが合っているか
  • UTM付きURLが正しく開くか
  • 投稿文が実際の記事内容と一致するか

この確認が終わってから、TXTの文章をコピーして投稿します。

まとめ

完全自動投稿が割に合わない場合でも、文章作成とURL付与だけなら無料で自動化できます。人が最終確認する工程を残しつつ、毎回の定型作業を減らせる現実的な方法です。
