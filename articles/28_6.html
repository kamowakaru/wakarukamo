ChatGPTで作った記事をWordPressへ自動投稿する方法｜OpenAI APIとREST APIを使う流れ

ChatGPTで作った記事をWordPressへ自動投稿する仕組みを、OpenAI APIでの生成とWordPress REST APIでの投稿に分けて解説します。

結論

ChatGPTで作った記事をWordPressへ自動投稿する仕組みは、OpenAI APIで記事データを生成し、内容を確認した後、WordPress REST APIへ投稿データを送る流れで作れます。

重要なのは「生成したら即公開」にしないことです。最初はWordPressへdraftとして保存し、タイトル、本文、カテゴリ、事実関係を確認してから公開する設計が安全です。

全体の流れ

処理は大きく5段階に分けます。

  1. 記事タイトルや指示を用意する
  2. OpenAI APIへ記事生成を依頼する
  3. 生成結果からタイトルと本文を取り出す
  4. QA・事実確認を行う
  5. WordPress REST APIへ投稿する

生成と投稿を分離すると、どちらで問題が起きたかも調べやすくなります。

OpenAI APIで記事を生成する

OpenAI APIを使う部分では、記事タイトル、対象読者、必要な見出し、禁止事項などを入力として渡します。

返ってきた文章をそのままWordPressへ送るのではなく、プログラム側で「タイトル」「本文」など必要な項目へ分けます。

APIのモデル名、リクエスト形式、認証方法は更新されるため、実装時点のOpenAI公式ドキュメントを確認してください。

WordPressへ送るデータを作る

WordPress REST APIで投稿を作成するときは、投稿用エンドポイントへPOSTリクエストを送ります。

基本のURLは次の形です。

https://example.com/wp-json/wp/v2/posts

送信データには、たとえば次の項目を含めます。

{
  "title": "記事タイトル",
  "content": "記事本文",
  "status": "draft"
}

WordPress REST APIでは投稿作成時にtitle、content、statusなどを指定できます。

最初はdraftで保存する

自動生成した記事を最初からpublishで送ると、確認前の文章が公開される可能性があります。

動作確認中は次のように下書きを指定します。

"status": "draft"

WordPress管理画面で内容を確認してから公開すれば、生成エラーや誤情報を見つけやすくなります。

WordPress側の認証を設定する

投稿作成は公開記事の取得と違い、認証が必要です。

WordPressの認証方法を確認し、外部アプリから投稿を作成できる権限を設定します。

認証情報はソースコードへ直接書いたり、GitHubの公開リポジトリへ保存したりしません。

カテゴリやタグはIDで扱う

WordPress REST APIでカテゴリやタグを投稿へ設定するときは、対象となるタームのIDを扱います。

AIにカテゴリ名からIDを推測させず、WordPress側から取得した正しいIDとの対応表を用意します。

自動投稿前にQAする

最低限、次を確認します。

  • 指定したタイトルになっているか
  • 本文が途中で切れていないか
  • 見出し構成が正しいか
  • 根拠のない数値や体験談がないか
  • URLやコードが正しいか
  • WordPressのカテゴリが正しいか

QAで問題があれば投稿処理へ進めないようにします。

重複投稿を防ぐ

API処理を再実行したとき、同じ記事が2件作成される可能性があります。

記事管理番号など一意の値を持たせ、すでにWordPressへ投稿済みか確認してから新規作成する仕組みを検討します。

エラーを記録する

OpenAI APIの生成失敗とWordPress REST APIの投稿失敗は別々に記録します。

HTTPステータス、エラー本文、対象記事番号などを残しておくと、再実行する範囲を判断しやすくなります。

まとめ

ChatGPTの記事をWordPressへ自動投稿する場合は、OpenAI APIでの生成、QA、WordPress REST APIへの投稿を別工程にします。最初は下書き保存にし、認証情報と重複投稿を管理したうえで、確認済みの記事だけを公開する流れにしてください。
