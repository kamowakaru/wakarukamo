GitHubへファイルをアップロードする方法｜ブラウザだけで追加・差し替え

GitHubのブラウザ画面からファイルやフォルダをドラッグ＆ドロップし、既存ファイルを差し替える手順を解説します。

結論

GitHubへ少数のファイルを追加するなら、専用ソフトを入れなくてもブラウザから操作できます。リポジトリのAdd file → Upload filesを開き、ファイルまたはフォルダをドラッグ＆ドロップして、最後に変更を確定します。

ワカルカモの更新では、受け取ったZIPをそのまま置くのではなく、ZIPを展開し、中にあるファイルを既存の構成へ重ねる方法を使いました。

新しいファイルを追加する手順

  1. GitHubで対象のリポジトリを開く
  2. Add fileを押す
  3. Upload filesを選ぶ
  4. 追加するファイルやフォルダを画面へ入れる
  5. 一覧に目的のファイルがあるか確認する
  6. 変更内容を表すメッセージを書く
  7. Commit changesで確定する

GitHub公式では、ブラウザから一度にアップロードできるのは100ファイルまで、1ファイルは25MiBまでと案内されています。GitHubへファイルを追加する方法

ZIPを受け取ったときの注意

ZIPは複数ファイルをまとめた圧縮ファイルです。GitHub Pagesで中身を公開したい場合、通常はZIPのまま置いてもサイトは更新されません。

パソコンでZIPを展開し、フォルダを開きます。さらに外側に更新用フォルダがある場合は、その中にあるassets、scripts、contentなどをリポジトリのトップへ入れます。

外側のフォルダごと入れると、wakarukamo/index.htmlのように階層が一つ増え、公開元にあるindex.htmlが更新されないことがあります。

既存ファイルを差し替える方法

同じ場所に同じ名前のファイルをアップロードすると、GitHub上では変更ファイルとして扱われます。

たとえば、次のファイルを更新するとします。

assets/js/site.js?v=20260914-2

アップロード先でも同じ階層を保つ必要があります。site.jsだけをリポジトリ直下へ置くと、元のファイルとは別物になるため注意してください。

アップロード前に確認すること

  • ZIPを展開したか
  • 外側のフォルダを余分に入れていないか
  • ファイル数が100以下か
  • 上書きしたいファイルと同じ階層か
  • パスワードやAPIキーが含まれていないか

とくに公開リポジトリへ認証情報を入れると、第三者から見える状態になります。測定IDのように公開を前提とする値と、アクセストークンやパスワードは分けて扱います。

ファイルが多い場合

100ファイルを超えるとブラウザから一度に追加できません。更新対象だけを分けるか、GitHub Desktopを使います。エラーへの具体的な対処は、GitHubで100ファイルを超えてアップロードできないときで説明しています。

まとめ

ブラウザからのアップロードは、小さな更新なら簡単です。ZIPを展開し、元と同じフォルダ構成を保ち、確定前にファイル一覧を確認することが失敗を防ぐポイントです。

ワカルカモポイント

差し替えるときは、ZIPではなく展開後の中身を、同じフォルダ構成のままリポジトリへ入れます。
