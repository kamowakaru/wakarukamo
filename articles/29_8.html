GitHub DesktopでCommit・Pushする方法｜ローカルの変更をGitHubに反映する手順

GitHub DesktopでPC上の変更を確認し、CommitしてからPushしてGitHubへ反映する手順を初心者向けに解説します。

親記事

GitHubとは？初心者向けにできること・使い方を解説

結論

GitHub DesktopでPC上の変更をGitHubへ反映する基本手順は、変更差分を確認 → Commit → Pushです。

CommitはPC上のGit履歴へ変更を記録する操作、PushはそのCommitをGitHubへ送る操作です。Commitだけで終わるとGitHub側へ反映されていない場合があります。

1. PC上のファイルを編集する

Cloneしたリポジトリのファイルをエディタで開き、必要な修正を行って保存します。

たとえばindex.htmlの見出しを変更します。

2. GitHub DesktopでChangesを見る

GitHub Desktopへ戻ると、変更されたファイルがChangesに表示されます。

ファイル名だけでなく差分も確認します。

意図していないファイルが変更されていたら、理由を確認してからCommit対象に含めるか判断します。

3. 対象ブランチを確認する

Commitする前に、現在選択されているブランチを確認します。

個人サイトでmainへ直接Commitする運用もありますが、チーム開発では作業用ブランチを使う場合があります。

運用ルールに合うブランチか確認します。

4. コミットメッセージを書く

変更内容が分かるSummaryを入力します。

トップページの見出しを修正

複数の無関係な変更をまとめず、1つの目的として説明できる単位でCommitすると履歴を追いやすくなります。

5. Commitする

変更対象とメッセージを確認してCommitします。

この時点では、ローカルリポジトリの履歴へ変更が記録されています。

GitHub上のリポジトリへまだ送られていない場合があります。

6. Pushする

Commit後、GitHub DesktopからPushを実行します。

Pushが完了すると、ローカルで作ったCommitがGitHub側へ送られます。

7. GitHubのWeb画面で確認する

ブラウザで対象リポジトリを開き、変更したファイルや最新のCommitを確認します。

GitHub Pagesを利用している場合は、リポジトリへの反映と公開サイトへの反映を分けて確認します。

Pushできないとき

GitHub側に自分のPCへまだ取り込んでいない変更があると、そのままPushできない場合があります。

エラーメッセージを確認し、必要に応じてGitHub側の変更を取得してから自分の変更との整合性を確認します。

競合が発生した場合は、どちらの内容を残すか確認して解決します。

秘密情報をCommitしない

Push前に、APIキー、パスワード、個人情報などが変更ファイルへ含まれていないか確認します。

誤って秘密情報をPushした場合は、GitHubからファイルを消すだけでなく、認証情報の無効化・再発行など必要な対応を行います。

まとめ

GitHub Desktopでは、変更差分とブランチを確認し、CommitしてからPushします。「保存した」「Commitした」「Pushした」は別の状態です。最後にGitHubのWeb画面で変更が反映されたことまで確認してください。

ワカルカモポイント

Commitはローカルの履歴への記録、PushはGitHubへの送信です。変更差分と対象ブランチを確認してからCommit・Pushします。
