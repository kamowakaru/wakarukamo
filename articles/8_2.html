GitHub Pagesの公開元はどれを選ぶ？ブランチとActionsの違い

GitHub Pagesのブランチ公開とGitHub Actions公開の違いを、ファイルの置き方と更新の流れから選べるように説明します。

選び方は「公開前に何をするか」

GitHub Pagesには、指定したブランチのファイルを公開元にする方法と、GitHub Actionsのワークフローで公開する方法があります。HTMLを手で作ってそのまま配信したいなら、まずブランチ公開が分かりやすいです。MarkdownからHTMLを生成するなど、独自のビルドが必要ならActions公開が向いています。

比べる点ブランチから公開GitHub Actionsから公開
公開元指定ブランチの/(root)または/docsワークフローが作った公開用ファイル
初期設定ブランチとフォルダーを選ぶワークフローを設定する
向いている例作成済みのHTMLをそのまま置くスクリプトで記事やページを生成する
更新時に見る場所公開元ブランチの変更とPagesの実行結果ワークフローのビルド・デプロイ結果

ブランチ公開でもGitHub内部ではPagesのデプロイ処理が実行されます。「Actionsタブに実行がある＝必ずActions公開を設定した」とは限りません。どちらを選んでいるかは「Settings」→「Pages」の「Build and deployment」→「Source」で確認できます。

ブランチ公開を選ぶ場合

「Deploy from a branch」を選び、たとえばmainの/(root)を指定します。公開ファイルをdocsフォルダーにまとめたなら/docsを選びます。それ以外の任意のフォルダーは、この選択欄では直接指定できません。公開元フォルダーの直下にindex.htmlなどの入口となるファイルがあるか確認してください。

GitHub標準のJekyll処理が不要な静的ファイルで、アンダースコアで始まるフォルダーなどもそのまま配信したい場合は、公開元に.nojekyllを置く構成もあります。必要がなければ最初から設定を増やさず、表示を確認してから検討します。

Actions公開を選ぶ場合

「Source」を「GitHub Actions」にすると、サイトのビルドと公開を行うワークフローを用意します。テンプレートから始めることもできます。ワークフローが成功したか、公開用の成果物にindex.htmlが含まれているかを確認します。設定だけ切り替えても、既存のスクリプトが自動でPagesに公開されるわけではありません。

ワカルカモの構成で考えると

ワカルカモではcontent/articles/のMarkdownを更新すると、.github/workflows/build-articles.ymlが動き、scripts/generate_site.pyで公開用HTMLを生成します。記事を生成するActionsと、PagesがそのHTMLを配信する設定は別の確認箇所です。現在のPagesのSourceと公開元を見て、生成されたarticles/が公開対象に入るかを確認します。反映されない場合は確認順の記事を参照してください。
