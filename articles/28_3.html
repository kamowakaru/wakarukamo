WordPress REST APIで投稿数・公開記事を確認する方法

WordPress REST APIで公開記事の件数や投稿データを確認する方法を、レスポンスヘッダーとページ分割の考え方を含めて解説します。

結論

WordPress REST APIで公開記事数を確認するときは、投稿一覧を取得したレスポンスのX-WP-TotalとX-WP-TotalPagesヘッダーを確認する方法があります。

本文のJSON配列に入っている件数だけを数えると、1ページ分しか数えていない可能性があります。

投稿一覧へアクセスする

基本のエンドポイントは次の形です。

https://example.com/wp-json/wp/v2/posts

ここから公開投稿の一覧を取得します。

X-WP-Totalを確認する

WordPress REST APIのコレクションでは、ページ分割されたレスポンスに総件数を示すヘッダーが含まれます。

X-WP-Total

この値を確認すると、条件に一致する投稿の総数を把握できます。

総ページ数は次のヘッダーです。

X-WP-TotalPages

ブラウザ画面だけではヘッダーが見えにくい

URLをブラウザで開くとJSON本文は見えますが、レスポンスヘッダーは通常のページ表示だけでは確認しにくいことがあります。

ブラウザの開発者ツールや、HTTPレスポンスを確認できるプログラムなどを使います。

1ページの件数と総記事数を混同しない

REST APIでは一覧がページ分割されます。

たとえばJSONに10件しか表示されていなくても、「サイトに公開記事が10件しかない」とは限りません。

全記事を取得したい場合は総ページ数を確認し、pageを変えて取得します。

公開記事だけを確認する

通常の公開投稿を対象にするなら、公開状態の投稿を取得する条件で確認します。

認証を使って編集権限のある投稿まで取得する処理では、下書きなど別の状態が対象になることがあります。

「公開記事数」を数えたいのか「WordPress内の全投稿数」を数えたいのかを先に決めます。

スプレッドシートと照合する場合

記事管理表とWordPressの公開記事を比べるなら、件数だけで一致と判断しない方が安全です。

管理番号、slug、URL、タイトルなど、双方で照合できるキーを決めて1件ずつ確認します。

件数が同じでも、別の記事が抜けている可能性があるためです。

まとめ

WordPress REST APIで公開記事数を見るときは、一覧JSONの件数ではなくX-WP-Totalを確認します。全件データが必要ならX-WP-TotalPagesも見て、ページを分けて取得してください。
