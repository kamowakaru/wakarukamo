Markdownで記事を管理してGitHub Pagesで公開する方法

Markdownで記事を管理し、GitHubで変更履歴を残しながらGitHub Pagesへ公開する基本構成と作業の流れを解説します。

親記事

Web作業を自動化する方法｜初心者向けに考え方と方法を解説

結論

Markdownで記事を管理してGitHub Pagesで公開するには、記事を.mdファイルとしてGitHubで管理し、サイト側の仕組みでHTMLへ変換・ビルドして、GitHub Pagesの公開対象へ反映します。

大切なのは、「Markdownファイルを管理する場所」と「ブラウザへ表示する完成サイト」を分けて考えることです。

基本構成を決める

自作の変換処理を使うなら、たとえば次のように分けます。

content/
  articles/
    1.md
    2.md
templates/
  article.html
scripts/
  build.py
dist/

contentには記事の元データ、templatesにはHTMLの共通構造、distには生成した公開用ファイルを置く構成です。

実際の構成は利用する静的サイトジェネレーターなどによって異なります。

記事をMarkdownで作る

記事ごとに.mdファイルを作ります。

---
title: "記事タイトル"
date: "2026-09-17"
---

## 結論

ここに本文を書きます。

front matterを使う場合は、サイト生成側で必要な項目と形式を統一します。

GitHubで履歴管理する

記事を追加・修正したらGitへCommitします。

記事本文がテキストなので、GitHub上で変更差分を確認できます。

大量の記事を管理する場合は、記事番号とファイル名の対応ルールを決めておくと重複や上書きを防ぎやすくなります。

HTMLへ変換する

公開前にMarkdown本文をHTMLへ変換し、記事テンプレートへ組み込みます。

自作スクリプトを使う方法のほか、Markdownを扱える静的サイトジェネレーターを使う方法があります。

GitHub Pagesがどのビルド・デプロイ方法に対応しているかは、現在のGitHub公式ドキュメントで確認してください。

GitHub Actionsでビルドを自動化する

記事をPushしたら自動でHTMLを生成したい場合、GitHub Actionsを利用できます。

概念的な流れは次のとおりです。

MarkdownをPush
↓
GitHub Actionsを実行
↓
MarkdownをHTMLへ変換
↓
サイトをビルド
↓
GitHub Pagesへデプロイ

変換に失敗した場合はデプロイしないようにします。

GitHub Pagesの公開設定を確認する

GitHub Pagesでは、リポジトリの設定で公開方法を構成します。

ブランチから公開する方法やGitHub Actionsを利用する方法などがあるため、現在の設定画面と公式手順に合わせます。

「ファイルをGitHubへPushできた」と「GitHub Pagesの公開サイトへ反映された」は別なので、両方を確認してください。

CSSや画像も用意する

Markdownから生成したHTMLだけでは、サイトのデザインや画像ファイルが不足する場合があります。

CSS、画像、JavaScriptなど必要な静的ファイルも公開用の構成へ含めます。

画像URLは、生成後のHTMLから見て正しいパスになるようにします。

公開前に確認する

最低限、次を確認します。

  • タイトルが正しい
  • Markdown変換に失敗していない
  • 内部リンクが正しい
  • 画像が表示される
  • コードブロックが崩れていない
  • CSSが読み込まれている
  • 公開対象でない下書きが含まれていない

Markdownを置くだけの構成との違い

GitHub上ではMarkdownファイル自体を閲覧できますが、それとGitHub Pagesの完成したWebページは同じものではありません。

ブログとしてデザインやURL構造を統一するなら、サイト生成の仕組みを用意して公開ページを作ります。

まとめ

Markdown記事をGitHub Pagesで公開する場合は、Markdownを原稿としてGitHubで管理し、HTMLへの変換・ビルド・デプロイを行います。GitHub Actionsを組み合わせれば、記事のPushをきっかけに公開用サイトを自動生成する流れも作れます。

ワカルカモポイント

Markdownをそのまま置くだけでなく、サイトの仕組みに合わせてHTMLへ変換・ビルドし、GitHub Pagesの公開元へデプロイする流れを作ります。
