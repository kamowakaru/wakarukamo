GitHub Actionsとは？できることを初心者向けに解説

GitHub Actionsとは何かを、Workflow、イベント、Job、Runnerなどの基本用語と、自動テスト・ビルド・デプロイの例から解説します。

親記事

Web作業を自動化する方法｜初心者向けに考え方と方法を解説

結論

GitHub Actionsは、GitHubのリポジトリで起きたイベントなどをきっかけに、あらかじめ決めた処理を自動実行する仕組みです。

たとえば、ファイルをPushしたらテストする、MarkdownからHTMLを生成する、ビルド後にサイトをデプロイするといった処理を自動化できます。

Workflowとは

GitHub Actionsで「いつ、何を実行するか」を定義するものがWorkflowです。

Workflowは通常、リポジトリ内の次のディレクトリへYAMLファイルとして保存します。

.github/workflows/

設定もGitHub上で履歴管理できるため、処理内容をコードと一緒に確認できます。

何をきっかけに実行できる？

Workflowはさまざまなイベントをきっかけに実行できます。

代表例は次のようなものです。

  • リポジトリへのPush
  • Pull Request
  • 手動実行
  • スケジュール
  • 他のWorkflowからの呼び出し

目的に合うイベントを選びます。

JobとStepの関係

Workflowの中には1つ以上のJobを定義できます。

Jobの中には、実際に順番に実行するStepを書きます。

イメージは次のとおりです。

Workflow
└─ Job
   ├─ Step 1
   ├─ Step 2
   └─ Step 3

たとえば「ファイルを取得する」「変換プログラムを実行する」「結果を確認する」といった処理をStepへ分けます。

Runnerとは

Jobを実際に実行する環境をRunnerと呼びます。

GitHubが提供するRunnerを利用する方法のほか、自分で管理するRunnerを使う方法もあります。

OSや必要なソフトウェアに応じて実行環境を選びます。

どんな自動化に使える？

Webサイト関連なら、次のような処理が候補です。

  • HTMLやCSSのチェック
  • MarkdownからHTMLへの変換
  • 静的サイトのビルド
  • テストの実行
  • GitHub Pagesへのデプロイ
  • 定期的なスクリプト実行

すべてをGitHub Actionsで行う必要はなく、GitHubリポジトリと相性のよい処理から使います。

秘密情報はSecretsなどで管理する

外部APIへ接続するWorkflowでは、APIキーやトークンが必要になることがあります。

秘密情報をWorkflowのYAMLへ直接書いてcommitしないでください。GitHubが提供するSecretsなど、用途に合った秘密情報管理の仕組みを使います。

実行結果を確認する

Workflowを作ったら、成功したかだけでなく、各JobやStepのログを確認します。

失敗時には、どのStepでエラーになったかを特定して修正します。

まとめ

GitHub Actionsは、GitHub上のイベントをきっかけにWorkflowを自動実行できる仕組みです。初心者は、手動実行やPushをきっかけに簡単な処理を動かし、Workflow・Job・Step・Runnerの関係を理解するところから始めると分かりやすくなります。
