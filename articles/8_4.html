GitHubで100ファイルを超えてアップロードできないときの対処法

GitHubのブラウザー画面で一度に100ファイルを超えて追加できない場合に、GitHub Desktopで変更を確認して反映する手順を紹介します。

100ファイルを超えたら、アップロード方法を変える

GitHubのブラウザー画面では、一度にアップロードできるファイルは最大100個です。これは「リポジトリ全体で100ファイルまで」という意味ではありません。少量ならアップロードを分ける方法もありますが、何度も多数のファイルを入れ替えるならGitHub Desktopで変更を管理すると作業しやすくなります。ファイル数とは別に、ブラウザーから追加するファイルには1ファイルあたりの容量制限もあります。

GitHub Desktopでまとめて反映する手順

  1. 公式サイトからGitHub Desktopを入れ、使用するGitHubアカウントでサインインします。
  2. 「File」→「Clone repository」で、変更先のリポジトリをパソコンへ複製します。保存先のフォルダーを控えます。
  3. 複製したフォルダー内の正しい場所へ新しいファイルをコピーします。既存ファイルを上書きするなら、名前とパスが意図したものか先に確かめます。
  4. GitHub Desktopの「Changes」で、追加・更新・削除されたファイルを確認します。予想外の大量削除が見えたらコミットせず、コピー先を見直します。
  5. 変更の概要を入力して「Commit to main」（ブランチ名は環境による）を押し、続けて「Push origin」でGitHubへ送ります。
  6. GitHubのリポジトリで変更後のファイルを開いて確認します。GitHub Pagesで公開するサイトなら、生成処理とPagesの公開結果も別途確認します。

Commitはパソコン内で変更を記録する操作、PushはGitHubへ送る操作です。 Commitだけでは公開リポジトリは変わりません。Windows 10とWindows 11のどちらでも、GitHub Desktopの基本的な操作の流れは同じです。

分けてブラウザーから入れる場合

100ファイル以下のまとまりに分け、毎回、アップロード先のフォルダーとコミット後のファイル一覧を確認します。途中で一部だけ公開される可能性があるため、HTMLとその画像やCSSを別々の回に分けるときは、すべて入れ終わるまでリンク切れに注意します。繰り返し行うならDesktopへ切り替えるほうが、変更一覧をまとめて確認できます。

ワカルカモではこう使います

記事の元ファイルはcontent/articles/にあります。まとめて記事を修正するときは、同名のMarkdownをそのフォルダーへ配置し、GitHub Desktopで変更一覧を見てからCommit・Pushします。その後、記事生成ワークフローと公開サイトを確認します。元記事を置き換える際は、4_1.mdのようなアンダースコアを含むファイル名も一致させます。

公開リポジトリにパスワードやAPIキーを含めないでください。機密情報は削除コミットだけでは履歴に残るため、誤ってPushした場合は速やかにキーを無効化し、必要な履歴削除も検討します。
