## 結論

記事数が増える前に、**1行を1記事として管理するCSV**を作ります。ファイル名、記事タイトル、親子関係、公開状況を同じ番号で結びつけるのがポイントです。

## 1. 必要な列を決める

ワカルカモの管理ファイル`data/article-management.csv`は次の7列で始まります。

| 列 | 入れる内容 |
|---|---|
| No. | 記事とファイルを結ぶ管理番号 |
| カテゴリ | サイト上の大分類 |
| グループ | 親子記事をまとめる単位 |
| 種別 | 親・子・孫 |
| タイトル | 公開する記事タイトル |
| 公開済 | 未・済 |
| アフィ候補 | 紹介できそうなサービス |

このサイトでは`No.`をMarkdownのファイル名と公開ページのURLにも使います。たとえば`8_1`行は`content/articles/8_1.md`、公開後は`articles/8_1.html`です。最初から列を増やしすぎると更新が止まりやすくなります。

## 2. 管理番号は文字列として扱う

`1_2`や`19_2_1`のように、親子関係が分かる番号にします。

```csv
No.,カテゴリ,グループ,種別,タイトル,公開済,アフィ候補
8,Web全般,GitHubPages,親,GitHub Pagesとは？,済,なし
8_1,Web全般,GitHubPages,子,GitHub PagesでWebサイトを作る方法,済,なし
```

ハイフンを使った`1-2`はExcelで日付に変換されることがあります。アンダースコアなら管理番号として表示されやすくなります。

## 3. ChatGPTに表を整えてもらう

③の記事一覧を貼り、次のように依頼します。

```text
次の記事一覧をCSV形式にしてください。
列は「No.,カテゴリ,グループ,種別,タイトル,公開済,アフィ候補」です。
No.は親を1、子を1_1の形式にし、公開済はすべて「未」、アフィ候補がなければ「なし」にしてください。
Excelで日付化しないよう、管理番号にハイフンは使わないでください。

【記事一覧】
```

出力後は、番号重複・列ずれ・タイトル内のカンマを確認します。上の2行は列の形を示す短い例で、実際に読み込ませるCSVでは公開する正確なタイトルを使ってください。

![Excelで開いた記事管理CSVの例](../assets/images/articles/article-management-csv-excel.png)

このように、1行を1記事として「No.」「カテゴリ」「グループ」「種別」「タイトル」「公開済」「アフィ候補」を並べます。親記事と子記事を番号でそろえておくと、記事数が増えても関係を追いやすくなります。

## 4. CSVをExcelで開くときの注意

日本語が文字化けする場合は、UTF-8のCSVとして保存します。Excelへ直接ダブルクリックで開くより、「データ」からCSVを読み込むと文字コードや列形式を指定しやすくなります。

編集後に保存するときも、CSV UTF-8形式を選びます。

## 5. 更新ルールを決める

記事を作るたびに、次の順で更新します。

1. CSVで「未」の記事を選ぶ
2. No.とタイトルを本文作成に使う
3. ファイル名を`No..md`にする
4. 公開する前に「公開済」を「済」へ変える
5. タイトルや番号を変更したらCSVとファイルを同時に直す

ワカルカモの生成処理では、`公開済`が「済」の行に載る記事だけが公開対象です。Markdownだけを追加してCSVを「未」のままにすると、公開ページは出力されません。逆に先に「済」へ変えた場合は、記事本文を確認してから生成します。自動生成の起動条件には記事Markdownの変更が含まれますが、CSVのみの変更は含まれません。CSVだけを直したときは生成処理を手動で実行してください。最新のCSVを正本にすると、どれが未作成か分からなくなるのを防げます。

## 今回の完成チェック

- 管理番号とファイル名のルールが決まった
- 未公開記事を絞り込める
- UTF-8で保存できた
