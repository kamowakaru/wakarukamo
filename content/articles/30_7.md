## 結論

MarkdownとHTMLの大きな違いは、**Markdownは文章を簡潔に書きやすくする記法、HTMLはWebページの構造をブラウザへ伝えるためのマークアップ言語**という点です。

ブログでは「記事本文はMarkdownで管理し、公開時にHTMLへ変換する」という使い分けができます。

## 同じ見出しを書くとどう違う？

Markdownでは次のように書きます。

```markdown
## 使い方
```

HTMLでは次のようになります。

```html
<h2>使い方</h2>
```

Markdownは記号が少なく、元のテキストをそのまま読んでも内容を把握しやすいのが特徴です。

## リンクの違い

Markdownでは次のように書きます。

```markdown
[公式サイト](https://example.com/)
```

HTMLでは次の形です。

```html
<a href="https://example.com/">公式サイト</a>
```

どちらも最終的にはWebページ上のリンクとして表現できます。

## 役割を比較する

| 項目 | Markdown | HTML |
|---|---|---|
| 主な用途 | 文章を簡潔に記述 | Webページの構造を記述 |
| 見出し | `## 見出し` | `<h2>見出し</h2>` |
| リンク | 簡潔に書ける | 属性など細かく指定できる |
| 元ファイルの読みやすさ | 高い | タグが多くなる |
| ブラウザ表示 | 変換が必要な場合がある | ブラウザが解釈できる |

## Markdownが向いている部分

記事本文のように、見出し、段落、箇条書き、リンク、画像、コードが中心ならMarkdownで書きやすくなります。

GitHubで記事ファイルを管理するときも、差分を確認しやすい形式です。

## HTMLが必要になる部分

ページ全体の構造や細かな属性を指定したい場合はHTMLを使います。

テンプレート側でヘッダー、ナビゲーション、記事領域、フッターなどをHTMLとして作り、記事本文だけMarkdownから変換する構成もできます。

## CSSはどこに入る？

MarkdownとHTMLは主に文章やページ構造を扱います。

文字色、余白、レイアウトなどの見た目はCSSで設定します。

Markdownで記事を書いても、HTMLへ変換後にCSSを適用すればサイト全体のデザインを統一できます。

## Markdown内でHTMLを使える？

Markdown処理系によっては、Markdown内へHTMLを直接書ける場合があります。

ただし、利用する変換ツールやサイトの設定によって扱いが異なります。

特定のHTMLに依存しすぎるとMarkdownのシンプルさが薄れるため、必要な部分だけ使います。

## ブログではどう使い分ける？

記事制作では次のように役割を分けられます。

```text
Markdown
記事本文・記事情報

HTMLテンプレート
ページ全体の構造

CSS
デザイン
```

Markdownを変換してHTMLテンプレートへ組み込めば、記事ごとに同じページ構造を手書きする必要がなくなります。

## まとめ

Markdownは記事を簡潔に書くために使いやすく、HTMLはブラウザへページ構造を伝えるために使います。どちらか一方だけを選ぶ必要はなく、記事はMarkdown、公開ページはHTMLという形で組み合わせられます。
