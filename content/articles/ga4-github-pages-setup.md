## 結論

GitHub PagesのサイトでもGA4を利用できます。GA4でプロパティとウェブデータストリームを作り、GoogleタグをHTMLへ追加したあと、リアルタイムレポートで自分のアクセスを確認します。

WordPress用プラグインは必要ありません。静的サイトでは、共通HTMLやJavaScriptからGoogleタグを読み込む形にします。

## GA4とSearch Consoleの違い

GA4は、サイトへ来た人がどのページを見たか、どこから訪れたか、検索窓を使ったかなどを確認するサービスです。

Search Consoleは、Google検索での表示回数、クリック、検索語句、インデックス状況を確認します。目的が違うため、サイト運営では両方を設定すると状況を把握しやすくなります。

## 1．GA4のプロパティを作る

Google Analyticsへログインし、アカウントとプロパティを作成します。プロパティ名は`ワカルカモ`のように、どのサイトか分かる名前にします。

タイムゾーンと通貨も設定します。あとからレポートの日付や集計時間に関係するため、運営地域に合わせて確認します。

## 2．ウェブデータストリームを作る

プラットフォームでは`ウェブ`を選び、GitHub Pagesの公開URLとストリーム名を入力します。

```text
https://kamowakaru.github.io/wakarukamo/
```

作成後、`G-`から始まる測定IDが発行されます。測定IDの場所が分からない場合は、[GA4の測定IDはどこにある？](ga4-measurement-id.html)を確認してください。

## 3．Googleタグをサイトへ入れる

Googleタグの案内に表示されるコードを、計測したい全ページの`head`内で読み込みます。

ワカルカモでは測定IDを設定ファイルに分け、共通JavaScriptがGoogleタグを読み込む構成にしました。こうすると、測定IDを変更するときに複数のHTMLを一つずつ直す必要がありません。

測定IDはサイト訪問者のブラウザにも送られる識別子で、パスワードやアクセストークンとは性質が異なります。ただし、管理画面へログインする情報やAPIの秘密鍵はリポジトリへ入れません。

## 4．GitHub Pagesへ反映する

変更したファイルをGitHubへコミットし、Pagesの公開が完了するまで待ちます。公開サイトのHTMLソースにGoogleタグが入っていることを確認します。

GitHub上のコードだけ更新され、公開ページが古い場合は、ActionsやPagesの状態を確認します。

## 5．リアルタイムで確認する

公開サイトを自分で開き、GA4の`レポート → リアルタイム`を確認します。ユーザー数やページパスが表示されれば、データが届いています。

Google公式によると、受信したデータはまずリアルタイムに表示され、その後ほかのレポートへ反映されます。[Google Analyticsレポートの概要](https://support.google.com/analytics/answer/9212670?hl=ja)

## まとめ

GitHub PagesへのGA4設定は、プロパティ作成、ウェブストリーム作成、測定IDの設置、リアルタイム確認の順に進めます。コードを入れただけで終わらず、公開サイトから実際にデータが届くところまで確認しましょう。
