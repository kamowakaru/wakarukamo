## GitHub Pagesとは

GitHub Pagesは、GitHubのリポジトリにあるWebサイトのファイルを公開できる機能です。HTML・CSS・JavaScriptで作った静的サイトに向いています。更新内容は、指定したブランチから公開するか、GitHub Actionsで作成した公開用ファイルを配置して反映します。リポジトリにファイルを置くだけではなく、Pagesの設定と公開結果まで確認する必要があります。

GitHub Freeでも公開リポジトリから利用できます。独自ドメインを使うなら、ドメインの取得・更新費用は別です。プランや利用条件は変更されることがあるため、利用前に公式の案内を確認してください。公開リポジトリにはパスワード、APIキー、個人情報を入れないでください。

## 公開までの道筋

1. GitHubにサインインし、サイト用のリポジトリを作る。
2. `index.html`など、ブラウザーで表示するファイルを用意する。
3. 「Settings」→「Pages」で公開元を設定する。
4. デプロイが完了したら公開URLを開き、見た目とリンクを確認する。

たとえばユーザーサイト用に`ユーザー名.github.io`という名前のリポジトリを作ると、基本のURLは`https://ユーザー名.github.io/`です。別名のリポジトリで作るプロジェクトサイトでは、通常`https://ユーザー名.github.io/リポジトリ名/`となり、CSSや画像のパスをルートから書くと表示が崩れる場合があります。実際の公開URLを開いて確認します。

## ブランチ公開とActions公開の違い

HTMLをそのまま置く小さなサイトなら、指定したブランチの`/(root)`または`/docs`から公開すると始めやすいです。MarkdownからHTMLを生成するなど、公開前に独自の処理が必要ならGitHub Actionsが選択肢になります。どちらを使うかは[公開元の選び方](./8_2.html)で詳しく説明します。

ワカルカモでは、記事のMarkdownから公開用HTMLを生成するワークフローがあります。Markdownを変更したら、生成処理が成功したかと公開サイトに反映されたかを別々に確認します。この流れは[更新が反映されないときの確認方法](./8_3.html)でも紹介しています。
