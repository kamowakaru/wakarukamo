## 結論

GASで処理を定期実行するには、**時間主導型トリガーを設定して、対象の関数を決まった間隔や時間帯に自動実行**します。

「毎日処理したい」「数時間ごとに表を確認したい」といった定期作業に利用できます。

## 最初に関数を手動実行する

トリガーを作る前に、自動化したい関数が手動で正常に動くことを確認します。

```javascript
function dailyProcess() {
  console.log('定期処理を実行');
}
```

スプレッドシート更新などを行う場合は、対象データが正しいかも確認します。

## トリガー画面を開く

Apps Scriptプロジェクトでトリガーの設定画面を開き、新しいトリガーを追加します。

設定項目では、実行する関数やイベントの種類を選びます。

画面名や配置は変更される場合があるため、表示が異なる場合はGoogle Apps Scriptの公式ドキュメントを確認してください。

## 時間主導型を選ぶ

イベントのソースとして時間主導型を選び、必要な実行間隔を設定します。

用途に応じて、一定間隔、日単位、週単位などの選択肢があります。

## 指定時刻ぴったりとは限らない

時間主導型トリガーは、一般的なサーバーのcronのように「毎日12:00:00ちょうど」の実行を前提にする用途とは考え方が異なります。

日単位のトリガーなどでは指定した時間帯の中で実行される仕組みがあるため、厳密な秒単位の時刻が必要な処理には向くか確認が必要です。

## プログラムからトリガーを作ることもできる

GASでは`ScriptApp`を使ってトリガーを作成できます。

```javascript
function createTrigger() {
  ScriptApp.newTrigger('dailyProcess')
    .timeBased()
    .everyDays(1)
    .atHour(9)
    .create();
}
```

この例は毎日の時間主導型トリガーを作る基本形です。

同じ関数を何度も実行してトリガーを重複作成しないよう注意してください。

## トリガーの重複を確認する

「処理が2回実行される」という場合は、同じ関数に複数のトリガーが登録されていないか確認します。

プログラムから作成する場合は、既存トリガーを確認してから追加する設計も検討します。

## 実行履歴を見る

自動処理が動かなかった場合は、Apps Scriptの実行履歴から成功・失敗を確認します。

権限、コードエラー、利用制限など、失敗理由を切り分けます。

## タイムゾーンを確認する

日時を扱う処理では、スクリプトプロジェクトのタイムゾーンと想定している地域が一致しているか確認します。

日付の切り替わりを使う処理では特に重要です。

## 利用制限も確認する

GASにはトリガーや実行時間などに利用制限があります。

大量処理や高頻度実行を設定する場合は、現在のGoogle Apps Script公式Quotasを確認してください。

## まとめ

GASの定期実行には時間主導型トリガーを使います。関数を手動テストしてからトリガーを設定し、重複登録、タイムゾーン、実行履歴を確認してください。厳密な時刻が必要な処理では、時間主導型トリガーの実行特性も考慮します。
