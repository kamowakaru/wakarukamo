## 結論

GASでGoogleフォームの回答を自動処理するには、**フォーム送信をきっかけに実行されるインストール型トリガーを設定し、送信時に渡されるイベント情報を処理**します。

フォームに紐づくスクリプトと、回答先スプレッドシートに紐づくスクリプトではイベントオブジェクトの内容が異なるため、どちらから処理するか先に決めます。

## 何を自動化するか決める

たとえば次のような処理があります。

- 回答内容を別シートへ整理する
- 条件に合う回答だけ抽出する
- 受付番号を発行する
- 回答後にメール処理を行う
- 他の管理表へデータを転記する

フォーム送信後に必ず行う定型処理が対象です。

## 回答先スプレッドシートから処理する例

フォーム回答をスプレッドシートへ保存している場合、そのスプレッドシートに紐づくApps Scriptからフォーム送信時トリガーを利用できます。

関数の例です。

```javascript
function onFormSubmit(e) {
  const values = e.values;
  console.log(values);
}
```

この`e`はトリガー実行時に渡されるイベントオブジェクトです。

## namedValuesを使う方法

回答先スプレッドシートのフォーム送信イベントでは、質問名をキーにした`namedValues`を利用できる場合があります。

```javascript
function onFormSubmit(e) {
  const named = e.namedValues;
  console.log(named);
}
```

列番号だけに依存する処理より読みやすくなる場合がありますが、質問タイトルを変更すると影響するため、運用ルールを決めます。

## トリガーを設定する

Apps Scriptのトリガー画面から、実行する関数とイベントの種類を選びます。

フォーム送信時に動かしたい場合は、対象となるスプレッドシートまたはフォームに対応する「フォーム送信時」のイベントを設定します。

Googleの画面表示は変更されることがあるため、現在の項目名は公式ドキュメントも確認してください。

## エディタから直接実行するとeがない

`onFormSubmit(e)`をエディタの実行ボタンから直接動かすと、実際のフォーム送信イベントが発生していないため、通常は期待する`e`が渡されません。

テストでは実際にフォームを送信するか、処理本体を別関数へ分けてテスト用データを渡します。

## 処理本体を分ける

```javascript
function onFormSubmit(e) {
  processAnswer(e.values);
}

function processAnswer(values) {
  // 回答を使った処理
}
```

こうすると、イベント受信とデータ処理を分けて考えられます。

## 二重処理を防ぐ

トリガーを重複して設定すると、同じ回答に対して処理が複数回走る原因になります。

受付番号やメール送信など重複が困る処理では、回答行や一意な値を使って処理済みか確認する方法を検討します。

## エラーを記録する

自動実行では画面を見ていないため、失敗に気付きにくくなります。

処理対象やエラー内容をログへ残し、必要に応じて通知する構成にします。

## まとめ

GASでフォーム回答を自動処理するときは、フォーム送信時トリガーとイベントオブジェクトを使います。どの種類のトリガーを使うかで取得できる情報が変わるため、回答先スプレッドシートから処理するのか、フォーム側から処理するのかを決めて実装してください。
