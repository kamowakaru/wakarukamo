## 結論

Markdown記事を公開するには、**MarkdownをHTMLへ変換し、共通のページ構造とCSSを適用する処理**を作ります。

記事ごとに完成HTMLを手作業で直すのではなく、元のMarkdownを修正して再生成できる状態を目指します。以下はワカルカモの実際のファイル配置に沿った例です。

## 1. フォルダを役割で分ける

```text
content/articles/   Markdown記事
assets/css/         デザイン
scripts/            変換処理
articles/           生成されたHTML
```

編集する元データと、公開用の生成結果を混ぜないようにします。

## 2. 共通HTMLを作る場所を決める

ヘッダー・記事領域・フッター・CSSの読み込みを共通化します。ワカルカモでは`templates/`にHTMLを置かず、`scripts/generate_site.py`の共通処理でページの外枠を作ります。これから作る別のサイトなら、次のようなテンプレートを独立したファイルにしても構いません。

```html
<!doctype html>
<html lang="ja">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <link rel="stylesheet" href="../assets/css/style.css">
  <title>{{ title }}</title>
</head>
<body>
  <main>{{ content }}</main>
</body>
</html>
```

`{{ title }}`と`{{ content }}`は独立テンプレートを使う場合の記入例です。ワカルカモのファイル内にこの記号や`templates/article.html`が存在するわけではありません。

## 3. ChatGPTに変換処理を作ってもらう

```text
content/articles内のMarkdownを読み込み、articles内へ同名のHTMLを生成するPythonスクリプトを作ってください。

要件：
- front matterのtitleとdescriptionを読み取る
- Markdown本文をHTMLへ変換する
- 共通HTMLへtitle、description、本文を差し込む
- 記事間のリンク先は公開HTMLのパスにそろえる
- data/article-management.csvの「公開済」が「済」の記事だけを公開する
- UTF-8で読み書きする
- 変換に失敗したファイル名を表示する
```

実行前に、必要なライブラリと起動コマンドも確認します。ワカルカモの現行スクリプトはPythonの標準ライブラリで動かします。サイトのルートフォルダーで次を実行します。

```bash
python scripts/generate_site.py
```

実行結果では公開記事数と下書き記事数が表示されます。`articles/8_1.html`が生成されたか確認し、ブラウザーでトップからこの記事まで開いてください。生成処理は`data/articles.json`や`sitemap.xml`も更新します。

## 4. まず1記事だけ変換する

いきなり全記事を変換せず、1記事で次を確認します。

- 日本語が文字化けしていない
- タイトルとdescriptionが入っている
- H2・H3・リスト・表が表示される
- CSSが読み込まれている
- 内部リンク先が`.html`になっている

問題があれば変換処理か共通のページ構造を直し、もう一度生成します。

## 5. 全記事を再生成できるようにする

1記事で問題がなければ、フォルダ内のMarkdownを一括変換します。記事本文を修正したときは、生成済みHTMLを直接編集せず、Markdownから作り直します。

## 今回の完成チェック

- Markdownと生成HTMLの保存場所が分かれている
- 共通のページ構造とCSSを使っている
- 1記事をブラウザで確認できた
- 内部リンクがHTMLを指している
- 同じコマンドで全記事を再生成できる
