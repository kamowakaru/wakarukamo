## 結論

GitHub DesktopでCloneするときは、**GitHub上の対象リポジトリを選び、PC上の保存先を指定してClone**します。

Clone後は、保存されたローカルフォルダを開き、目的のファイルが入っていることを確認してください。

## GitHub Desktopを開く

GitHub Desktopを起動し、必要に応じてGitHubアカウントへサインインします。

対象リポジトリへアクセスできるアカウントか確認します。

## Cloneするリポジトリを選ぶ

GitHub DesktopからリポジトリをCloneする操作を開きます。

GitHub.com上のリポジトリ一覧から選ぶ方法や、リポジトリURLを指定する方法があります。

似た名前のリポジトリがある場合は、Ownerも確認します。

## Local pathを確認する

Clone前に、PCのどこへ保存するか指定します。

たとえば次のようなフォルダです。

```text
C:\Users\ユーザー名\Documents\GitHub\my-website
```

実際の保存場所は自分の環境に合わせます。

後から編集するときに場所が分からなくならないよう、普段使う作業フォルダへまとめると管理しやすくなります。

## Cloneを実行する

対象リポジトリと保存先を確認したらCloneを実行します。

完了すると、GitHub Desktopでそのリポジトリが選択された状態になります。

## ローカルフォルダを開く

Clone後は、GitHub Desktopからリポジトリのフォルダを開きます。

HTML、CSS、Markdownなど目的のファイルが取得できているか確認します。

## ファイルを編集する

Cloneしたファイルは、VS Codeなど普段使っているエディタで編集できます。

編集して保存すると、GitHub DesktopのChangesに変更内容が表示されます。

## CloneしただけではGitHubは変わらない

CloneはGitHub上のリポジトリをPCへ取得する操作です。

CloneしただけでGitHub側のファイルが変更されることはありません。

PCで編集した内容をGitHubへ反映するには、その後CommitとPushを行います。

## ZIPダウンロードとの違い

GitHubからZIPとしてファイルを取得する方法もありますが、CloneではGitリポジトリとしてPCへ取得します。

そのため変更履歴を管理し、GitHubとのPull・Pushを行えます。

継続して編集するプロジェクトならCloneが向いています。

## Cloneできないとき

対象リポジトリへのアクセス権、サインインしているGitHubアカウント、リポジトリURL、PCの保存先などを確認します。

Privateリポジトリでは、アクセス権のないアカウントからはCloneできません。

## まとめ

GitHub DesktopでCloneするときは、対象リポジトリとLocal pathを確認して実行します。Clone後はローカルフォルダの内容を確認し、編集後にCommit・PushしてGitHubへ変更を反映します。
