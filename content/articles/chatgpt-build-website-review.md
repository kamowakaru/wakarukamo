## 結論

ChatGPTを使うと、Webサイトの構成案、HTML・CSS・JavaScriptの作成、エラーの原因調査まで幅広く手伝ってもらえます。ただし、最初の指示だけで理想どおりのサイトが完成するわけではありません。

ワカルカモでは、画面のイメージを伝え、生成されたサイトを実際に開き、「ここを消したい」「画像を変えたい」「スマホ表示を直したい」と修正を重ねました。AIは制作を速くしてくれますが、完成形を決めるのは人です。

## 今回ChatGPTと作ったもの

ワカルカモを公開するまでに、次の作業を相談しました。

- サイト名と発信テーマの整理
- パソコンとスマホのデザイン案
- HTML・CSS・JavaScriptの作成
- カテゴリとタグの設計
- 記事ページの自動生成
- カテゴリ別サムネイルの選択
- GitHub Pagesへの公開
- Search ConsoleとGA4の設定
- X・Threads用投稿原稿の生成

単にHTMLを書くだけでなく、サイトを公開して計測するところまで、一連の作業を分けて進めています。

## AIに任せやすかった作業

特に相性がよかったのは、仕様が言葉で説明できる作業です。

たとえば「記事データから一覧カードを表示する」「スマホではメニューを折りたたむ」「記事追加時にSNS用文章も作る」といった要望は、入力と出力が明確です。コードのひな型作成や、複数ファイルの修正候補を整理する用途に向いていました。

エラー画面のスクリーンショットを見せて、次に押す場所を確認する使い方も便利でした。ただし、画像にアカウント名やメールアドレス、アクセストークンなどが写っていないかは確認が必要です。

## 一度ではうまくいかなかったこと

デザインは言葉だけでは細かな印象が伝わりにくく、色だけ違う似た画像が増えたり、不要な装飾が残ったりしました。そのため、参考画像を示しながら次のように具体化しました。

- カモの画像は残し、HTML文字だけ消す
- 図形ではなく通常のイラスト画像にする
- お問い合わせフォームは置かない
- 企業からの掲載依頼だけ受けられる案内にする

「いい感じにして」より、残すものと消すものを分けて伝えたほうが修正が安定します。

## 人が確認する必要がある部分

AIが作ったコードは、必ずブラウザで動作確認します。リンク切れ、スマホ表示、画像パス、公開URLの違いなどは、実際の環境で初めて分かることがあります。

文章も同様です。サービスの料金や最新画面、公式仕様は変わる可能性があるため、公式情報を確認します。AIがもっともらしく書いた内容を、そのまま事実として公開しないことが大切です。

## 作りやすかった進め方

今回うまく進んだ順番は次のとおりです。

1. サイトの目的を決める
2. 参考デザインを作る
3. 最小構成をブラウザで確認する
4. 機能を一つずつ追加する
5. GitHub Pagesで公開する
6. 公開後の画面を確認する
7. Search ConsoleとGA4を接続する

GitHub Pagesそのものの公開方法は、[GitHub PagesでWebサイトを作る手順](github-pages-create-website.html)で詳しく説明しています。

## まとめ

ChatGPTを使えば、専門知識が必要な部分を質問しながらWebサイトを形にできます。大切なのは、一度で完成させようとせず、作業を小さく分けて実際の画面を確認することです。制作過程の失敗や修正も、次に同じことで困る人へ役立つ情報になります。
