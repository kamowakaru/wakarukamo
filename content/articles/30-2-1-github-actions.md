## まず知っておきたいポイント

GitHubはGitリポジトリをオンラインで管理し、変更履歴、共同作業、Issue、Actionsなどを利用できるサービスです。
公開リポジトリには誰でも見られる情報だけを置き、パスワードやAPIキーをcommitしないようにします。

初心者のうちは用語を丸暗記する必要はありません。「何のための機能か」「自分の作業ではどこで使うか」まで分かれば、別の画面やサービスでも応用しやすくなります。

## 実際に進めるときの流れ

1. **対象を確認する**  
   操作するサイト、アカウント、ファイル、シートなどが正しいか確認します。
2. **必要な設定だけ変更する**  
   一度に複数の設定を変えず、記事タイトルの目的に必要な箇所だけ操作します。
3. **結果を確認する**  
   保存しただけで終わらず、表示・出力・公開状態など最終結果を確認します。
4. **うまくいかなければ直前の変更から戻る**  
   エラー文や変更前の値を控えておくと切り分けやすくなります。

## ワークフローの最小イメージ

```yaml
name: Build site
on:
  push:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.x'
      - run: python generate_site.py
```
これは「mainへpush → リポジトリ取得 → Python準備 → `generate_site.py` 実行」までの例です。GitHub Pagesへ実際にデプロイする場合は、現在の公式Pages用Actionsを使ったアップロード・デプロイ工程も必要です。

## 画面や仕様が記事と違うときは

Webサービスは画面名、料金、利用上限、提供機能が変更されることがあります。ボタンの位置が少し違うだけなら同じ役割の項目を探し、料金・権限・公開範囲・API仕様など重要な点は公式情報を確認してください。

## よくある失敗・注意点

- 操作するアカウントやサイトを取り違えたまま設定を変更する。
- 一度に複数の設定を変えて、どの変更が効いたのか分からなくなる。
- 保存・commit・公開・デプロイなど、最後の反映工程を確認せず「変わらない」と判断する。
- パスワード、APIキー、個人情報などを公開ファイルやスクリーンショットへ含める。

元に戻しにくい操作では、変更前の値やファイルを残してから進めると安全です。

## よくある質問

### Webサイトは無料でも作れる？

GitHub Pagesなど無料で公開できる方法があります。一方、独自ドメイン、レンタルサーバー、有料サービスを使う場合は費用がかかります。

### 独自ドメインは最初から必要？

必須ではありません。まず無料URLで試し、運営を続ける段階で独自ドメインを検討する方法もあります。
