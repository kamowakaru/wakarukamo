## 結論
Markdownをmasterにし、PushをきっかけにActionsで変換スクリプトを実行すると、記事HTMLを手作業で更新せずに済みます。変換失敗時はexit codeを非0にして公開工程を止めます。

## 仕組みを考えるポイント
自動化やサイト管理では、まず「元データは何か」「どの処理がそれを変換するか」「最終成果物は何か」を分けます。途中で失敗したときに、どこまで成功したか分かるログも残します。

## 実際に組むとき
小さなサンプルで処理を動かし、入力1件で期待する出力になることを確認してから件数を増やします。削除・上書き・公開を伴う処理は、テスト用データや下書き状態で先に検証します。

## ワカルカモではこう使っています
ワカルカモでは記事本文をMarkdownで管理し、GitHub Actionsから生成スクリプトを実行してHTMLを作る構成です。記事ファイルや管理データに問題がある場合は生成処理を失敗させ、公開前に気づけるようにしています。

## 処理イメージ
```text
Markdown / 管理CSV
        ↓ Push
GitHub Actions
        ↓
generate_site.py
        ↓
HTML・一覧・サイトマップ等
```

## まとめ
Markdown→HTML自動変換では、便利さだけでなく**変更しやすさ・失敗を検出できること・元に戻せること**まで含めて設計すると運用しやすくなります。
