## 結論

ブログ記事のサムネイルをカテゴリ別に自動選択するには、**「カテゴリ → 使用する画像」の対応表を作り、記事データのカテゴリをキーにして画像を決める**仕組みにします。

記事ごとに画像ファイル名を手入力するより、カテゴリ名を正しく管理するだけで共通画像を使えるため、記事数が増えたときの設定漏れを減らせます。

## カテゴリと画像の対応を決める

たとえば次のようにします。

| カテゴリ | サムネイル |
|---|---|
| AI・ChatGPT | `/images/thumb-chatgpt.webp` |
| Google・GAS | `/images/thumb-google.webp` |
| Web全般 | `/images/thumb-web.webp` |
| WordPress | `/images/thumb-wordpress.webp` |

この対応表をテンプレートや設定ファイルなど、1か所で管理します。

## 記事データにはカテゴリを持たせる

Markdownならfront matterへカテゴリを入れます。

```yaml
---
title: "記事タイトル"
category: "Web全般"
---
```

ビルド時に`category`を読み取り、対応する画像を選びます。

## JavaScriptで考える場合の例

仕組みを単純化すると、次のような対応になります。

```javascript
const thumbnails = {
  'AI・ChatGPT': '/images/thumb-chatgpt.webp',
  'Google・GAS': '/images/thumb-google.webp',
  'Web全般': '/images/thumb-web.webp',
  'WordPress': '/images/thumb-wordpress.webp'
};

const thumbnail = thumbnails[category] || '/images/thumb-default.webp';
```

実際のサイトでは、使用している静的サイト生成処理やテンプレートに合わせて実装します。

## デフォルト画像を用意する

新しいカテゴリを追加したのに対応表を更新し忘れることがあります。

その場合に画像が壊れないよう、フォールバック用の画像を用意します。

```text
カテゴリが対応表にある
→ カテゴリ画像

カテゴリがない
→ default画像
```

同時に、未登録カテゴリをログへ出すと設定漏れに気付きやすくなります。

## カテゴリ名の表記を統一する

`Web全般`と`Web 全般`のように表記が違うと、別カテゴリとして判定されます。

記事管理CSVなどを正本にしている場合は、カテゴリ名を勝手に変更せず、その値と画像対応表を一致させます。

## 一覧ページと記事ページで共通利用する

サムネイルの判定処理を一覧ページだけに書くと、関連記事など別の場所で違う画像になる可能性があります。

画像を決定する処理を共通化し、同じ記事なら同じサムネイルを返す構成にします。

## 個別画像を優先したい場合

一部の記事だけ専用画像を使いたいなら、記事データに個別画像を設定できるようにします。

```text
個別画像あり
→ 個別画像を使う

個別画像なし
→ カテゴリ画像

カテゴリ画像もなし
→ default画像
```

優先順位を決めておけば処理が複雑になりにくくなります。

## 公開前に確認する

自動選択を導入したら、次を確認します。

- 全カテゴリに対応画像がある
- 画像パスが正しい
- 一覧で画像が表示される
- 記事ページでも意図した画像になる
- 新カテゴリでdefault画像へ切り替わる
- 画像の縦横比が大きく崩れない

## まとめ

カテゴリ別サムネイルは、カテゴリと画像の対応表を共通設定として持ち、記事カテゴリから自動決定します。デフォルト画像と個別画像の優先ルールも決めておくと、記事数やカテゴリが増えても管理しやすくなります。
