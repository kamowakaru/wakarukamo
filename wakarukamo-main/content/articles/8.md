## まず知っておきたいポイント

GitHubはGitリポジトリをオンラインで管理し、変更履歴、共同作業、Issue、Actionsなどを利用できるサービスです。
公開リポジトリには誰でも見られる情報だけを置き、パスワードやAPIキーをcommitしないようにします。

初心者のうちは用語を丸暗記する必要はありません。「何のための機能か」「自分の作業ではどこで使うか」まで分かれば、別の画面やサービスでも応用しやすくなります。

## GitHub Pagesでサイトを公開する基本の流れ

1. GitHubへサインインし、サイト用のリポジトリを作成します。
2. `index.html` など公開したいファイルをリポジトリへ追加します。
3. リポジトリの「Settings」→「Pages」を開きます。
4. ブランチから公開する場合は公開元ブランチとフォルダを選び、保存します。独自のビルド処理がある場合はGitHub Actionsを使う方法もあります。
5. デプロイ完了後、表示されたGitHub PagesのURLを開いて確認します。

## 環境によって確認場所が違う

- **レンタルサーバー・FTP**：アップロード先のディレクトリ、ファイル名、大文字小文字、更新日時を確認します。
- **GitHub Pages**：リポジトリのcommitだけでなく、Pages/Actionsのデプロイ結果まで確認します。
- **WordPress**：管理画面の設定に加えて、キャッシュ・最適化系プラグインやサーバー側設定の影響も考えます。
- **Netlifyなどのホスティング**：最新デプロイが成功しているか、公開対象のブランチやビルド設定が正しいか確認します。

使っていない環境の手順まで全部試す必要はありません。自分の公開方法に該当する部分だけ確認してください。

## 画面や仕様が記事と違うときは

Webサービスは画面名、料金、利用上限、提供機能が変更されることがあります。ボタンの位置が少し違うだけなら同じ役割の項目を探し、料金・権限・公開範囲・API仕様など重要な点は公式情報を確認してください。

## よくある失敗・注意点

- 操作するアカウントやサイトを取り違えたまま設定を変更する。
- 一度に複数の設定を変えて、どの変更が効いたのか分からなくなる。
- 保存・commit・公開・デプロイなど、最後の反映工程を確認せず「変わらない」と判断する。
- パスワード、APIキー、個人情報などを公開ファイルやスクリーンショットへ含める。

元に戻しにくい操作では、変更前の値やファイルを残してから進めると安全です。

## よくある質問

### GitHub Pagesは無料で使える？

基本機能は無料で利用できます。ただし独自ドメインを使う場合は、ドメイン自体の取得・更新費用が別途かかります。

### 独自ドメインも使える？

はい。GitHub Pagesの設定とドメイン側のDNS設定を行えば、独自ドメインで公開できます。
