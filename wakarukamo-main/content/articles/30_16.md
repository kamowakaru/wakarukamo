## 結論

ブログを作るときは、**Markdownは記事を書くための形式、HTMLはWebページの構造、CSSは見た目**と考えると整理しやすくなります。

3つは競合するものではありません。Markdownで書いた記事をHTMLへ変換し、そのHTMLへ共通CSSを適用する構成にできます。

## 役割を比較する

| 種類 | 主な役割 | 例 |
|---|---|---|
| Markdown | 記事本文を簡潔に書く | `## 見出し` |
| HTML | Webページの構造を表す | `<h2>見出し</h2>` |
| CSS | 色・余白・レイアウトを指定 | `h2 { ... }` |

記事の内容とデザインを分離できるのがポイントです。

## Markdownは記事を書く

Markdownでは、見出しやリンクを簡単な記号で表現できます。

```markdown
## 使い方

[公式サイト](https://example.com/)
```

テキストとして読みやすく、Gitで変更差分も確認しやすいため、記事原稿の管理に向いています。

## HTMLはページの構造を作る

ブラウザへ表示するページではHTMLが使われます。

```html
<article>
  <h2>使い方</h2>
  <p>ここに本文が入ります。</p>
</article>
```

ヘッダー、記事領域、フッターなどの構造もHTMLで表します。

## CSSはデザインを担当する

CSSでは見出しの大きさや本文幅などを指定します。

```css
article {
  max-width: 800px;
  margin: 0 auto;
}
```

複数ページから同じCSSを読み込めば、共通デザインを一括変更できます。

## ブログでは組み合わせて使う

たとえば次の流れです。

```text
Markdownの記事
↓
HTMLへ変換
↓
共通HTMLテンプレートへ組み込む
↓
CSSを適用
↓
Webページとして公開
```

記事を書くたびに完成HTMLを最初から手書きする必要がなくなります。

## どれから覚える？

記事制作が目的なら、Markdownの基本記法から始めるとすぐに原稿を書けます。

その後、HTMLでページ構造、CSSでデザインを調整する仕組みを理解すると、公開サイト全体を管理しやすくなります。

## まとめ

Markdown・HTML・CSSは役割が違います。記事はMarkdown、ページ構造はHTML、見た目はCSSへ分けると、記事追加とサイト全体のデザイン変更を別々に管理できます。
