## 結論

Search ConsoleのHTMLファイルでGitHub Pagesの所有権を確認する場合は、**Search Consoleから取得した確認用HTMLファイルを、GitHub Pagesで公開されるサイトのルートからアクセスできる場所へ置きます**。

重要なのは、確認ファイルの名前や中身を変更しないことと、Search Consoleが指定するURLをブラウザで直接開ける状態にしてから「確認」を実行することです。

## 1. Search ConsoleでHTMLファイルを取得する

URLプレフィックスのプロパティで所有権確認を進め、HTMLファイルを使う確認方法を選びます。

表示された確認用ファイルを取得します。ファイル名は確認情報を含んでいるため、分かりやすい名前へ変更しないでください。

## 2. GitHub Pagesの公開元を確認する

GitHub Pagesで使っているリポジトリを開き、どのブランチ・フォルダーが公開元になっているか確認します。

`index.html` が公開ルートにある単純な構成なら、確認用HTMLファイルも同じ階層へ置くと分かりやすくなります。

## 3. 確認用HTMLファイルを追加する

GitHub上でファイルを追加するか、ローカル環境からコミットしてリポジトリへ反映します。

このとき、確認用ファイルの中身を編集したり、拡張子を変えたりしないようにします。

## 4. GitHub Pagesへの反映を待つ

コミットした直後は、公開サイトへ反映されるまで少し時間がかかる場合があります。

Search Consoleに表示された確認URLをブラウザで開き、確認用ファイルの内容が表示されることを確認します。404になる場合は、配置場所、ファイル名、GitHub Pagesの公開元を見直します。

## 5. Search Consoleで確認する

確認URLへアクセスできる状態になったら、Search Consoleへ戻って所有権確認を実行します。

成功したらプロパティを利用できます。

## 確認後もファイルを削除しない

所有権確認が完了した後も、Googleが後から所有権を再確認する場合があります。

確認用HTMLファイルは、特別な理由がない限り公開場所に残しておきます。

## まとめ

GitHub PagesでHTMLファイルによるSearch Consoleの所有権確認を行う場合は、確認ファイルを公開ルートから指定URLで開ける場所へ置きます。ブラウザで確認URLが開けることを確かめてからSearch Consoleの確認ボタンを実行してください。
