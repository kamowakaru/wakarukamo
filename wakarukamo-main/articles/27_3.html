REST APIとは？初心者向けに仕組みをわかりやすく解説

REST APIとは何かを、HTTP、URL、リクエスト、レスポンス、JSONなどの基本用語と一緒に初心者向けに解説します。

結論

REST APIは、Web上のデータや機能を扱うAPIでよく使われる設計方法です。

初心者が最初に押さえたいのは、決められたURLへHTTPリクエストを送り、APIからレスポンスを受け取るという流れです。データの取得にはGET、作成にはPOSTなど、処理に応じたHTTPメソッドが使われます。

RESTとは

RESTは「Representational State Transfer」の略で、Webの仕組みを利用してデータや機能へアクセスするための考え方です。

RESTの考え方に沿って提供されるAPIを、一般にREST APIやRESTful APIと呼びます。

URLで操作する対象を指定する

REST APIでは、記事、ユーザー、商品などの対象をURLで表します。

たとえば記事一覧を扱うAPIなら、次のような形です。

https://example.com/api/posts

特定の記事を扱う場合は、IDを含むURLになることがあります。

https://example.com/api/posts/123

実際のURL構造はAPIごとに異なります。

HTTPメソッドで処理を伝える

同じURLでも、HTTPメソッドによって処理を分ける設計があります。

代表的な使い分けは次のとおりです。

HTTPメソッド主な用途
GETデータを取得する
POST新しいデータを作成する
PUT / PATCHデータを更新する
DELETEデータを削除する

すべてのAPIが同じメソッドを同じ形で提供しているとは限らないため、利用するAPIの仕様を確認します。

リクエストとレスポンス

APIへ送る要求をリクエスト、APIから返ってくる結果をレスポンスと呼びます。

リクエストにはURLやHTTPメソッドのほか、必要に応じて認証情報やパラメータ、送信データを含めます。

レスポンスには処理結果やデータ、エラー情報などが含まれます。

JSONでデータをやり取りすることが多い

REST APIでは、JSON形式がよく使われます。

{
  "id": 123,
  "title": "記事タイトル"
}

プログラム側では、このデータから必要な項目を取り出して表示や保存などに使います。

ステータスコードも確認する

HTTPレスポンスにはステータスコードがあります。

たとえば200番台は処理が成功した場合に使われ、400番台や500番台ではエラーを示します。ただし、具体的にどのコードを返すかはAPIの仕様で確認します。

認証が必要な操作もある

公開データの取得は認証なしでできても、投稿の作成や更新には認証が必要なAPIがあります。

APIキーなど認証情報を使う場合は、コードや公開リポジトリへそのまま載せないよう管理します。

まとめ

REST APIでは、URLで対象を指定し、GETやPOSTなどのHTTPメソッドを使ってリクエストを送ります。レスポンスはJSONなどで返されることが多く、実装時はURL、メソッド、認証、パラメータ、レスポンス形式を公式ドキュメントで確認してください。
