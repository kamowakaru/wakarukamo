ブログのデザインを全記事まとめて変更する方法｜共通CSSで管理するメリット

ブログのデザインを全記事まとめて変更する方法を、共通CSSの仕組み、HTML側の読み込み、変更時の確認ポイントとともに解説します。

結論

ブログのデザインを全記事まとめて変更したいなら、各記事が同じCSSファイルを読み込む構成にして、共通CSSを修正します。

記事ごとのHTMLへ色や文字サイズを直接書いていると、変更のたびに多数のファイルを修正する必要があります。共通CSSへ集約すると、デザイン変更箇所を減らせます。

HTMLとCSSの役割を分ける

基本的には、

HTML
見出し・本文・リンクなどの構造

CSS
色・サイズ・余白・配置などの見た目

として管理します。

たとえば記事ページから共通CSSを読み込みます。

<link rel="stylesheet" href="/css/style.css">

すべての記事が同じstyle.cssを参照すれば、そのファイルの変更を共通反映できます。

見出しをまとめて変更する

たとえばH2の余白を変更する場合です。

article h2 {
  margin-top: 2.5rem;
  margin-bottom: 1rem;
}

全記事のH2が同じ構造なら、各HTMLを編集する必要はありません。

記事領域へ限定する

単純に、

h2 {
  ...
}

とすると、記事以外のH2にも影響する場合があります。

記事本文をarticleや専用classで囲み、

.article-body h2 {
  ...
}

のように対象を限定すると管理しやすくなります。

共通classを使う

注意ボックスなどを記事ごとに別のclass名で作ると、一括変更しにくくなります。

<div class="note">
  注意内容
</div>

のように共通classを使えば、

.note {
  padding: 1rem;
  border: 1px solid;
}

と1か所で管理できます。

インラインスタイルを減らす

HTMLへ直接、

<p style="font-size:18px;">

のように書くと、共通CSSより個別指定が優先される場合があります。

全記事のデザインを一括管理したいなら、記事ごとのインラインスタイルを増やしすぎないようにします。

CSSを分割する方法

サイトが大きくなったら、役割ごとに分ける方法もあります。

base.css
layout.css
article.css
components.css

ただし、小規模サイトで細かく分けすぎると逆に管理しにくくなります。変更頻度や役割に合わせます。

Markdown記事でもCSSは共通化できる

MarkdownからHTMLを生成している場合も、生成後のHTMLへ共通classや共通CSSを適用します。

Markdown本文へデザイン情報を大量に書かず、テンプレートとCSS側で見た目を管理できます。

変更前に影響範囲を確認する

共通CSSは便利ですが、1回の変更が多数のページへ影響します。

変更後は次のようなページを確認します。

  • 通常の記事
  • 長いタイトルの記事
  • 表がある記事
  • コードブロックがある記事
  • 画像がある記事
  • スマートフォン表示

代表的なパターンを確認します。

ブラウザキャッシュにも注意する

CSSを更新したのに見た目が変わらない場合、古いCSSがブラウザや配信側のキャッシュに残っている可能性があります。

ファイルが正しく公開されているかを確認したうえで、キャッシュの影響も切り分けます。

まとめ

ブログのデザインを全記事まとめて変更するには、HTMLとCSSを分離し、全記事で共通CSSを読み込みます。記事本文のclassも統一し、変更後は複数種類のページと画面幅で表示を確認してください。
