ChatGPTでブログを作ってみた⑦｜GitHubへ登録してGitHub Pagesで公開する

作成したブログをGitHubへ登録し、GitHub Pagesで公開して、実際のURLからトップページと記事ページを確認する手順を紹介します。

結論

サイト本体と記事ページができたら、GitHubへファイルを登録し、GitHub Pagesの公開元を設定します。

この回の完成物は、第三者もブラウザから開ける公開URLです。ファイルをGitHubへ置いただけでは公開完了ではないため、Pagesの設定と公開後の動作確認まで行います。

1. GitHubのリポジトリを作る

GitHubへログインし、新しいリポジトリを作ります。名前は半角英数字とハイフンで、サイト内容が分かるものにします。

公開サイトとして使う場合は、公開範囲や登録するファイルに個人情報・秘密鍵・APIキーが含まれていないか確認します。

2. GitHub Desktopへリポジトリを取り込む

ブラウザから大量のファイルをアップロードすると制限に当たりやすいため、ファイル数が多い場合はGitHub Desktopを使います。

  1. GitHub Desktopでリポジトリをクローンする
  2. 作成したサイト一式をローカルのリポジトリへ入れる
  3. 変更一覧で追加対象を確認する
  4. 内容が分かるメッセージでCommitする
  5. PushしてGitHubへ送る

index.htmlが想定した階層にあるか確認します。

3. GitHub Pagesを設定する

リポジトリの設定からPagesを開き、公開元を選びます。

単純なHTMLサイトなら、指定ブランチのルートを公開元にする方法があります。生成処理を自動化する場合はGitHub Actionsを使う方法もあります。

どちらを選ぶ場合も、現在のサイト構成に合う公開元を指定します。

4. 公開処理の完了を確認する

設定後すぐに表示されない場合があります。Actionsを使っている場合は、実行履歴を開いて処理が成功しているか確認します。

エラーが出た場合は、エラーになった工程と赤字のメッセージをChatGPTへ渡し、原因候補を絞ります。画面全体ではなく、エラーメッセージを文字で渡すと確認しやすくなります。

5. 公開URLを実際に開く

公開URLで次を確認します。

  • トップページが表示される
  • 記事一覧を開ける
  • 記事本文が表示される
  • CSSと画像が読み込まれる
  • 内部リンクが404にならない
  • スマートフォンでも表示できる

PC内で表示できても、公開先ではファイル名の大文字・小文字や相対パスの違いでリンク切れすることがあります。

6. 更新の流れを1回試す

記事の一文を修正し、Commit・Push・公開反映まで試します。

Markdown修正
→ HTML再生成
→ Commit
→ Push
→ Actions確認
→ 公開URL確認

この流れが再現できれば、今後の記事追加にも使えます。

今回の完成チェック

  • リポジトリに秘密情報が含まれていない
  • GitHub上にサイト一式がある
  • Pagesの公開元を設定した
  • 公開URLでトップと記事を開けた
  • CSS・画像・内部リンクを確認した
  • 修正から再公開まで1回試した
